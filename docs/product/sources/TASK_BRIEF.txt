# AI_RULES.md

This document is critical.

PRD is the source of truth.

AI MAY:

* Generate Positive cases.
* Generate Negative cases.
* Generate Edge cases.
* Perform reasonable QA inference.
* Test documented boundaries.
* Connect related documented requirements.

AI MUST NOT:

* Invent business rules.
* Invent permissions.
* Invent roles.
* Invent fields.
* Invent API endpoints.
* Invent HTTP methods.
* Invent HTTP status codes.
* Invent payload structures.
* Invent limits.
* Invent undocumented system behavior.

Example:

Requirement:

`Password minimum 8 characters.`

Allowed:

* 7 characters.
* Exactly 8 characters.
* More than 8 characters.

Not allowed:

`Password maximum 50 characters`

unless explicitly documented.

Ambiguous requirements must be marked:

`Need Confirmation`

# VERSIONING_RELEASE.md

TestPilot AI uses Semantic Versioning:

```text
MAJOR.MINOR.PATCH
```

Examples:

```text
0.1.0
0.1.1
0.2.0
1.0.0
```

Use Conventional Commits.

Examples:

```text
feat: add PRD upload
fix: handle invalid PDF
docs: update PRD
test: add parser tests
refactor: simplify AI service
chore: update dependencies
```

Expected version behavior:

```text
fix → PATCH
feat → MINOR
breaking change → MAJOR
```

Use Husky as a Git quality gate.

Hooks may validate:

* lint
* typecheck
* tests
* commit message format

Version must NOT automatically increase on every local push.

Expected flow:

```text
Feature Branch
→ Commit
→ Husky Validation
→ Push
→ Pull Request
→ Merge Main
→ Automated Versioning
→ Release
```

Document how the version can be referenced by QA for:

* Test execution.
* Bug reporting.
* Regression.
* Retesting.
* Release tracking.
