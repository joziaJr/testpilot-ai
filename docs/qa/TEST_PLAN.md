# MVP Test Plan

## Purpose and evidence status

This business-feature inventory is reconciled to the approved [PRD](../product/PRD.md) and [Business Flow](../product/BUSINESS_FLOW.md). M0 provides the runners; M1 adds validation; M2 adds extraction; M3 adds structured analysis; M4 adds human review/selection; M5 adds explicit FE/BE/Both generation with strict grounding, IDs, and minimal result visibility. Implemented details are in [M1 Upload](../engineering/M1_UPLOAD.md) through [M5 Generation](../engineering/M5_TEST_CASE_GENERATION.md). No Actual Result or execution Status is assigned to unexecuted cases.

Turn planning items into cases only with source-backed expectations. The [approved OQ-03–OQ-14 decisions](../product/OPEN_QUESTIONS.md) now provide upload, language, eligibility, session, schema, TSV, retry, privacy, and release oracles. No unresolved MVP-blocking Open Questions remain. TestPilot's 10 MB limit must not be inferred for another uploaded target PRD.

## Integration and quality follow-through

In addition to approved product behavior, recommended engineering validation includes safe text rendering, prompt-injection resistance, server-side validation despite bypassed browser checks, stale-response/session isolation, and spreadsheet-formula handling under the agreed export policy. These checks assess safeguards and must not invent target-system requirements. See [Security](../engineering/SECURITY.md).

For long content/counts, record actual dimensions and usability observations; no initial numerical performance SLO is required. File maximum is approved as 10 MB. Test centralized configured timeout/context/resource values once implemented, and record exact byte conversion/model configuration used so boundary checks are reproducible.

## Execution approach

1. Read the approved sources and resolve only the remaining questions needed for the selected coverage.
2. Identify the version/build, environment, source revision, provider/model, and prompt/schema revisions where relevant.
3. Create evidence-backed FE/BE case specifications with stable IDs, using [Test Case Guide](TEST_CASE_GUIDE.md).
4. Prepare documented synthetic fixtures and approved failure controls under [Test Data Guide](TEST_DATA_GUIDE.md).
5. Run P0 first, then P1/P2 and affected regression. Separate mock-based and live-provider evidence.
6. Record actual observations only after execution. File only observed defects and link all artifacts through [Traceability](TRACEABILITY.md).
7. Assess [Release Checklist](RELEASE_CHECKLIST.md) against the exact candidate.

## Completion criteria and current limitations

Coverage is complete only when required behavior has sourced expectations, cases, actual execution evidence, and reviewed results. Release-critical failures and unanswered acceptance questions must be resolved before claiming QA readiness. M1–M5 specifications, fixtures, and deterministic automation exist; live-model quality results and later preview/export workflow coverage remain separate work. No manual execution or release clearance is implied. See [Traceability](TRACEABILITY.md) for source-to-coverage mappings.
